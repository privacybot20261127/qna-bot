# 작업계획서 — 개인정보·신용정보 법령 QnA 챗봇 (RAG)

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 신협 개인정보·신용정보 법령 QnA 챗봇 (가칭 **CU-LawBot**) |
| 일시 | 2026. 11. 27.(금) 1일 (09:00 ~ 18:00, 17:30 시연) |
| 목적 | 사내 시스템에 붙일 수 있는 웹 챗봇으로, 직원이 개인정보·신용정보 처리 관련 질문을 하면 **근거 조문과 함께** 답변 |
| 학습 대상 | ① 개인정보 보호법 ② 같은 법 시행령 ③ 신용정보의 이용 및 보호에 관한 법률(신용정보법) ④ 같은 법 시행령 — 출처: 국가법령정보센터(law.go.kr) |
| 결과물 | GitHub 공개 저장소 + 로컬에서 실행하는 웹 데모 |

## 1. 시스템 구성 (RAG)
```
[법령 원문] → 조문 단위로 자르기 → LLM으로 가상 QnA 만들기(JSONL) → 임베딩 → ChromaDB
                                                                              ↓
[웹 UI] ⇄ [FastAPI /api/chat] → 질문 임베딩 → 비슷한 QnA·조문 top-k 검색 → LLM이 근거 조문 인용해 답변
```

## 2. 기술 스택
| 구분 | 선택 | 이유 |
|---|---|---|
| 언어 | **Python 3.11** | RAG·임베딩 라이브러리가 가장 많음 |
| 백엔드 | **FastAPI + Uvicorn** | REST API라서 나중에 사내 시스템에서 바로 호출 가능 |
| 프론트 | **HTML/CSS/JS (정적 페이지 1장)** | 빌드 도구가 필요 없고 사내 포털에 iframe으로 넣기 쉬움 |
| 임베딩 | **BAAI/bge-m3** (sentence-transformers, 로컬) | 한국어 성능이 좋고 무료이며 데이터가 외부로 나가지 않음 |
| 벡터DB | **ChromaDB** (로컬 파일) | 설치만 하면 되고 별도 서버가 필요 없음 |
| LLM | **Claude API** (`claude-opus-5-5`, `.env`에서 변경 가능), 키는 `.env`로 관리 | 한국어 법률 문장을 잘 다룸. 사내에 도입할 때는 망분리 정책에 따라 로컬 LLM(Ollama 등)으로 바꿀 수 있게 설계 |
| 협업 | GitHub (Issues, PR, master 브랜치 보호) | — |

## 4. GitHub 작업 규칙
- 브랜치: `master`(보호, PR로만 병합) ← `feat/data-qna`, `feat/rag-api`, `feat/web-ui`, `docs/readme`
- 커밋 메시지: `feat:` `fix:` `data:` `docs:` `chore:` + 한 줄 요약 / PR마다 최소 1명이 리뷰
- 이슈 1개 = 작업 1개 (위 일정표의 각 행), 라벨: `data` `backend` `frontend` `docs`

## 5. 보안·리스크 관리
- **API 키는 `.env`에만 저장**(`.gitignore`에 등록됨). 저장소에는 `.env.example`만 올림. 커밋 전 `git status`로 확인
- 실제 조합원 정보나 내부 문서는 **사용 금지** — 공개 법령 원문과 가상 QnA만 사용 (법령은 저작권 보호 대상이 아님, 저작권법 제7조)
- 화면에 "본 답변은 참고용이며 법률 자문이 아닙니다. 최신 법령과 준법감시부서 확인이 필요합니다" 면책 문구 표시
- 리스크: 환각 답변 → 근거 조문을 반드시 함께 출력하고 검색 점수가 낮으면 답변을 거부 / 법 개정 → 시행일을 메타데이터로 저장
